### New / changed shapes and error codes
- **Spin attempts (H1).** `run_retention_cleanup` no longer clears `token_hash` on the stale decline (state `declined`, error `stale`, context null). `get_spin_attempt_status`, `prepare_spin_attempt`, `commit_spin_attempt`, `cancel_spin_attempt`: an attempt whose `token_hash` is `''` (the 90-day scrub of finished attempts, or its fan was deleted) answers `{status:'declined', error:'stale'}` for any request hash, never `conflict`. `conflict` is now only a live attempt whose link or request hash differs. A declined attempt past 90 days is deleted (`absent`); a committed one past 90 days answers `declined/stale` (decided by the coordinator: the saved request is released; the win is in the fan's history). App side already maps `stale` to the terminal `db_error` (`src/lib/data/spinAttempts.ts:65`), which `classifySpinStatus` releases.
- **Attribution (M1).** `messages.actor_id` / `redemptions.actor_id`: the trigger restores the old stamp only while that account exists, so `ON DELETE SET NULL` goes through. A deleted seat leaves `actor_id = null` (no orphan). No shape change for readers (already nullable).
- **Free-text rules (M2).** A DB-03 CHECK is added fully validated, or not at all when a row breaks it (never NOT VALID). Per skipped rule: `WARNING: 0073 (DB-03): N row(s) in public.<table> break <constraint> (<expr>); the rule is NOT in force until they are shortened and 0073 is re-run`. Closing block, one line: `WARNING: 0073 (DB-03): free-text size rules NOT in force (...): <names>` or `NOTICE: 0073 (DB-03): every free-text size rule is in force`. Re-running 0073 after shortening adds the rule.
- **Locks (M3).** First statement of 0073: a DO block with `set_config('lock_timeout','5s',true)` (= SET LOCAL, without the warning a statement-by-statement replay prints; LOCK TABLE needs the block anyway) and `LOCK TABLE ... IN ACCESS EXCLUSIVE MODE` on every public table, `spin_attempts` first. A table held by another session for more than 5 s: `ERROR: canceling statement due to lock timeout` (55P03), the whole migration rolls back, re-run is safe.
- **Control characters (L2).** `set_chat_settings`, `set_creator_note`: refuse `[[:cntrl:]]` other than tab / CR / LF (same class as `set_display_name`); accents, emoji and every script pass under C and UTF-8 locales. Errors unchanged (`22023` "invalid chat settings" / "invalid creator note").
- **Lock order (L3, L6).** `record_fan_ack`: profile key share before the fan. `reset_creator_content`: games (FOR UPDATE, id order) before the fans are deleted. The single-fan delete needed no change (its Focus game and prize are taken by the first BEFORE trigger, before its redemptions).
- **Reserved names (L7).** `_reserved_name(text)`: invisible characters (zero-width, joiners, direction marks, variation selectors, fillers, tags) are dropped first; for the whole-name tests the non-ASCII separators (Unicode spaces, dashes, dots, connectors, combining marks, punctuation and symbol blocks) are removed like `space _ . -`; a leading `@` is dropped after that. Both classes are code-point lists in the function (`\uXXXX`), read by `reservedNames.test.ts`. TS side: `nameWords()` drops the same invisible characters (src/lib/reservedNames.ts); test 1489 checks, incl. "every character the SQL drops folds to nothing in TS".
- **Agency names (L7).** `org_create(p_name)` raises `22023` `reserved agency name` (after the existing `42501` `account is not active`). A direct INSERT or rename of `orgs.name` by anyone (session, service) raises the same `22023` `reserved agency name` (trigger `ab_org_name`); an unchanged legacy name is not re-checked. PostgREST: `{ code: "22023", message: "reserved agency name" }`. The app has no rename path today (grep: no `orgs` update in src).
- **Owner state notices (L8).** `agency_owner_suspended` is written when the owner stops being live for either reason (suspended OR approval withdrawn), once per transition, to every seat and managed creator; `details` is now `{ org_name, org_id }`. When the owner is live again, that agency's `agency_owner_suspended` notices are deleted (matched on `details.org_id`).
- **org_briefs (INFO, replaces the managed-creator branch of `orgs_tie_read`).** New table `public.org_briefs (org_id uuid pk → orgs on delete cascade, name text, owner_active boolean)`, trigger-maintained from `orgs` (insert / any update / delete cascade), RLS on, one policy `org_briefs_read`: `can_act_for(self,'view')` and `org_id = own profiles.org_id`. `authenticated` holds SELECT only; anon nothing. `orgs_tie_read` is now seat-only: a managed creator no longer reads the `orgs` row (owner_id, billing_model); a seat still does, also while the owner is suspended. Column grants on `orgs` were not possible: owners read `owner_id` / `billing_model` (privacy.ts:403, admin.ts:212, seatScope.ts:112) and a column grant cannot differ by row. Reader changed: `src/lib/data/admin.ts` getAgencyOverview reads `org_briefs(org_id, name)` for the managed tie (was `orgs(id, name)`). `owner_active` for a managed creator: `org_briefs.owner_active`; for a seat: `orgs.owner_active` (admin.ts:246 still reads the owner's profile through the FK embed, which RLS hides: use the column). db.types has `org_briefs`.
- **legal_terms_notice (INFO).** `authenticated` holds column SELECT on `singleton, upcoming_version, effective_at, announced_at` only (no table SELECT): `select announced_by` → `42501`. The two RPCs are unchanged (the app reads only through them).
- **Expired links (INFO).** `creator_obligations` (`unplayedPaidSpins`, `unplayedSpins`, `activeLinks`) and `creator_fan_summaries.active_links` count an expired link like a paused one.
- **search_path loop (INFO 8).** On hosted, `ALTER FUNCTION` on a function the migration role does not own fails with `42501 must be owner of function` and would roll 0073 back. Now such a function is skipped: `WARNING: 0073 (DB-15): <fn> is owned by another role and keeps search_path=public; its owner must run: alter function ...`, and the closing check raises only for functions the migration role owns (others: a WARNING naming them).
